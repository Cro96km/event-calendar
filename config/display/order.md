# order.json の書き方(記入例)

`order.json` は、**セクション・小見出し・行の並びの唯一の設定**です。小見出しの**名前も個数も、このファイルが正本**で、コードは変更しません(増やす・改名する・並べ替える・消すが、すべてここだけでできます)。JSON にはコメントを書けないため、記入例はこのファイルに置きます(各キーの意味は `order.json` の先頭の `_doc`、詳細は `docs/spec.md` §4.3.8)。直接編集してください。書式の誤りは `npm run check` と CI が検知します。

## 小見出し(`groups`)の基本

`groups` は `quest` / `campaign` / `gacha` のセクションごとの配列で、**配列の順がそのまま表示順**です。1つの小見出しは次の項目で決まります。

| 項目 | 意味 |
|---|---|
| `name` | 表示名(自由に改名できる) |
| `role` | コードが特別扱いする役割。名前を変えても役割は残る。クエストは `event`(イベントガチャの写し)・`raid`(降臨)・`super`(超究極)、ガチャは `event`・`regular`(定例)。各1つ必須 |
| `match` | どの項目が入るか。`"words"`=自分の `words` を項目名に含む / `"name"`=自分の `name` を項目名に含む / `{"includes": [語, …]}` / `{"pattern": "正規表現"}`。書かなければ名称では入らない |
| `words` | `sort` が `fixed` のときの並びの語。`match` が `"words"` なら、入る項目の判定も兼ねる |
| `sort` | 行の並び方。`fixed`=`words` の順(項目名に含む語を上から。一致しない行は `"*"` の位置、書かなければ末尾)/ `name`=表示名の五十音順 / `start`=開始順(既定)/ `builtin`=コード固定(`role` が `event` と `super` のもの) |
| `then` | `fixed` で同じ順位の行の並び。`name`(既定)か `start` |
| `aliases` | 項目名にこの語を含めばこの小見出しに入れる(キャンペーン用。例 `CM視聴` → ミッション) |
| `late` | 他の小見出しの判定のあとで判定する。「クエスト」のような包括的な語用 |
| `default` | どの小見出しにも入らない項目の受け皿。クエストとガチャに1つ必須 |

**判定の順**は、`late` でない小見出しを配列の順に、次に `late` の小見出し、最後に `default` です。

## 小見出しを改名・並べ替える

`name` を書き換えるだけです(役割は `role` で決まっているので、動作は変わりません)。下の例は、定例クエストを「毎月のクエスト」に改名し、期間限定クエストを絶級クエストの前に移しています。配列は**そのセクションの全部**を書きます。

```json
{
  "groups": {
    "quest": [
      { "name": "イベントクエスト", "role": "event", "sort": "builtin" },
      { "name": "毎月のクエスト", "match": "words", "words": ["覇者の塔", "絶級トーナメント", "禁忌の獄", "破界の星墓", "未開の幻洞"], "sort": "fixed", "then": "start" },
      { "name": "常設クエスト" },
      { "name": "期間限定クエスト", "match": { "includes": ["クエスト"] }, "sort": "name", "late": true },
      { "name": "絶級クエスト", "role": "raid", "match": { "pattern": "^(轟絶|黎絶|滅絶) .+降臨$" }, "words": ["滅絶", "黎絶", "轟絶"], "sort": "fixed" },
      { "name": "超究極クエスト", "role": "super", "match": { "includes": ["超究極"] }, "sort": "builtin" },
      { "name": "その他", "default": true }
    ]
  }
}
```

**注意**: 名前を変えたら、`manual.json` や `overrides.json` の `group` に書いてある旧名も直してください(`npm run check` が誤りとして知らせます)。

## 小見出しを足す

配列に1行足します。下の例は、キャンペーンに「新しい企画」を足し(項目名に「新企画」を含む項目が入る。並びは名前順)、末尾の「ミッション」は名称では入れず `aliases` だけで入れています。

```json
{
  "groups": {
    "campaign": [
      { "name": "ノーマルクエスト", "match": "name" },
      { "name": "新しい企画", "match": { "includes": ["新企画"] }, "sort": "name" },
      { "name": "英雄の神殿", "match": "name", "sort": "fixed", "words": ["ノーコン", "タイムボーナス", "*", "特L"] },
      { "name": "ミッション", "sort": "name", "aliases": ["CM視聴"] }
    ]
  }
}
```

- 上の例の「英雄の神殿」は、`words` の順に並べます。項目名に語を含む行がその順になり、どれにも一致しない行は `"*"` の位置に入ります。
- キャンペーンの小見出しで `match` が `"name"` のものは、名称にその名前を含む項目をキャンペーンセクションに入れる判定にも使われます(2行表示の「対象」にもなります)。`match` を書かない小見出し(ミッション)は、振り分けには使われません。
- 小見出しを消すときは、その行を消します。消した小見出しに入っていた項目は、クエスト・ガチャでは `default` の小見出しに入ります。キャンペーンでは、名称で振り分けていた小見出し(`match` が `"name"`)を消すと、キャンペーンのカテゴリの記事の項目は「その他」に、イベントの記事の項目はクエストセクションに移ります。

## セクションを足す・並べ替える(`sections`)

```json
{
  "sections": [
    { "id": "character", "label": "キャラクター", "hue": 215, "categories": ["character"] },
    { "id": "quest", "label": "クエスト", "hue": 215, "categories": ["event"] },
    { "id": "special", "label": "特別企画", "hue": 40, "categories": [] },
    { "id": "campaign", "label": "キャンペーン", "hue": 215, "categories": ["campaign", "web-shop"] },
    { "id": "gacha", "label": "ガチャ", "hue": 215, "categories": ["collab"] }
  ]
}
```

- 上から順に表示します。上の例では、キャラクターが一番上で、「特別企画」がクエストとキャンペーンの間に入ります。
- `id` は英小文字・数字・ハイフン、`hue` は色相(0〜359)、`sat` は彩度(0〜100。省略は16)、`lit` は縁・線の明るさの補正(−15〜15。省略は0)です。`character`・`quest`・`campaign`・`gacha` は必須です(振り分けの判定がコードにあります)。`character` は新限定・獣神化・獣神化改・真獣神化の行で、`categories` は `["character"]` のままにします(docs/spec.md §4.13)。
- 足したセクションは小見出しを持ちません。項目は `config/schedule/overrides.json` の `section`(`"section": "special"`)で入れます。`categories` は空にします。
