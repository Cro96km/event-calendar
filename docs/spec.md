# 仕様書: monst-event-calendar

## 1. 目的・前提
- モンスト公式ニュース(https://www.monster-strike.com/news/)の告知からイベント/キャンペーン期間を抽出し、かつてアプリ内にあった「カレンダー」(2022 Ver.25.0〜2026/8 Ver.32.0で終了)を週表示で再現する。
- ローカルで動かすWebアプリ。公開用には表示範囲(今日から過去12か月・未来12か月。§4.8)・表示対象のみを静的ビルドして GitHub Pages で配布する（§5.2）。
- 費用ゼロ。外部DBサーバは使わない。

## 2. 構成
週1回の自動収集(Actions)+手動実行、表示/非表示の振り分け、GitHub Pages での公開(表示範囲は過去12か月・未来12か月)。

設計の方針: ①フロントは**静的JSONのみを読む**(ローカルもPagesも同一成果物) ②正本はgit管理可能なJSONファイル ③収集と表示は疎結合(CLIがJSONを書き、UIは読むだけ)。

## 3. 用語
- 記事: 公式ニュースの1ページ(ID=`YYYYMMDD_N`)。
- イベント(期間): 記事本文から抽出した「名称+開始+終了」。1記事に複数ありうる。
- ゲーム日: **4:00 JST 区切りの1日**。ゲーム日Dの範囲は半開区間 `[D 4:00, D+1 4:00)`（旧カレンダーの日切替が4:00であることに由来）。
  - イベント `[start, end]` はゲーム日Dに表示する ⇔ `start < D+1 4:00` かつ `end > D 4:00`（終了が丁度4:00なら翌ゲーム日には出さない。3:59終了は前ゲーム日のみ）。
  - 「今日」: カレンダー(週の起点・今日の強調・今日ボタン)は列が暦日なので `todayJstDay()`(JST 0:00切替)。ゲーム日の `todayGameDay()`(0:00〜3:59は前日)は日別詳細の判定用に残す。日付計算はこの1か所の共通関数に集約し、境界値テストを書く。ブラウザのローカルTZは使わない。

## 4. 機能要件
### 4.1 収集
- `npm run collect [-- --pages N --since YYYY-MM-DD]`
- 一覧(`/news/`, `/news/index_N.html`)を新しい順に巡回し、記事ID・タイトル・カテゴリ・公開日・URLを取得。更新検知の補助に `sitemap-news.xml` の `lastmod`(直近100件)を使い、正本に保存する(`lastmod`)。
- **詳細を取得する条件**: 正本に未登録、または `lastmod`/一覧の更新表示(追記)が前回取得より新しい記事。sitemapが及ばない古い記事は `--since` 指定時のみ全件照合。
- 初期は**全カテゴリ**を保存。
- 礼節(正本: operations.md §4): UA明記、間隔2秒以上、並列1、gzip、404は記録してスキップ、429は即中断(Retry-After尊重)、5xxは最大3回リトライ(指数バックオフ)後中断、robots.txtでDisallowのパスは取得しない。初回バックフィルは数日に分けてよい。
- 実装: `src/scraper/`(`list.ts` 一覧/sitemap、`detail.ts` HTML→行、`http.ts` 礼節付きfetch、`robots.ts`、`cache.ts`、`scrape.ts` 取得+reparse)。CLIは `npm run scrape -- --pages N` / `npm run reparse`。取得済み判定はキャッシュmtime < sitemap `lastmod` のとき再取得(一覧の「追記」表示は付きっぱなしで新旧を判別できないため判定に使わない。sitemap圏外の古い記事の追記検知は未対応)。3xxは追従せずエラー。
- データ: `src/data/{record,export,store,collect}.ts`、`scripts/collect.ts`。`--since` 指定時は公開日が since 以上の記事に限り、sitemap圏外でも未キャッシュなら詳細取得し、公開日が since より古い記事を含むページで巡回を止める(`--pages` は上限。`--since` のみなら既定200)。既定は `--pages 2`。429/5xxで中断しても取得済み分を正本・exportに保存し、非0終了。内容(fetched_at以外)が変わらない記事は書き換えない(差分なし)。終了時に今回/全体の ok/partial/none 件数を表示し `data/runs.log` に追記。
- 生HTMLは `data/raw/`(git管理外)にキャッシュし、パーサ変更時は `npm run reparse` で再取得なしに再解析。
- 規約・礼節の確認結果は docs/operations.md §4。

### 4.2 期間抽出(最重要リスク)
**前処理**: テキスト化時にNFKC正規化(全角数字・全角コロン→半角)、区切り `～〜~－−ー` を `〜` に統一、`12時00分`/`12時` を `12:00` に、表セルは連結(`12:00` と `11:59` が別行/別セルでも1範囲として結合)。
**フォールバック**: ▼見出し形式で何も取れなかった記事(none)に限り、▼の無い『期間』ラベル(数字を含まない短い行 `…期間`・表ヘッダ `開催期間 対象の年代`・見出し(h2/h3)`キャンペーン開催期間`。`受取` を含むものは除く)の直後の期間を取る(`period.ts` `parseWith(…, true)`)。期間行の並びが終わったら(期間でない行が来たら。期間を取る前でも)ラベルを閉じ、別の見出しにも持ち越さない。見出しのラベルは項目名にせず、名前は記事タイトル(`title_named`、複数行は `#1,#2…`。同ラベルは §4.3.2 で1行に統合)。**年代の表**(ヘッダに「年代」を含む列がある表。ガチャ「モンストジェネレーション」)は、各行の期間に続く年代(`2013＆2014、2015、2016`)ごとに1イベントを作る: 名前は `ガチャ「<記事タイトルのガチャ名> <年代>」`(例 `ガチャ「モンストジェネレーション 2013＆2014」`。記事の同名見出しがあればそのアンカーを付ける)。行の期間が重なっても日別枠に畳まない(年代ごとに期間が違いうる)。例: モンパスお試しキャンペーン(開催期間見出し)は記事タイトルが名前。タイトルの日付だけから期間を作ることはしない。
**日替わりピックアップ(Vol)**: ガチャ記事の `・Vol.N` / `期間：…` / `対象キャラ：…` の並び(ガチャ「モンコレDX」)は、Vol ごとに1イベント(名前 `ガチャ「モンコレDX Vol.1」`、ラベル `日替わりピックアップ`)。Vol の期間が既存の全体期間(開始・終了が一致)を覆うときは全体期間の行は作らない(覆わなければ残す)。`対象キャラ` は details(ラベル「対象キャラ」、キャラ名のみ)に保存し詳細パネルに出す。ガチャ名が取れないタイトルでは行わない。ジェネレーションの年代別の行(上記)には、記事の `▼排出対象の限定キャラクター`(`、`区切りのキャラ名)を同名の見出しの項目の details(ラベル「排出対象の限定キャラクター」)として付ける(他の「排出対象…」見出しは対象外)。定例ガチャ内の並びは年代順・Vol順(`gachaEra`)。
**見出し抽出**: `▼.*(期間|期限)` を広く対象にする(出現期間・開催期間・ガチャ開催期間・販売期間・排出期間・対象期間・ログインスタンプ開催期間 等。実記事20261015_2で確認)。

| パターン | 例 | 処理 |
|---|---|---|
| 完全形 | `2026年10月27日（火）12:00～11月21日（土）11:59` | 開始・終了 |
| 空白あり/なし | `2026年10月16日（金） 12:00～11月2日（月） 11:59` | 空白許容 |
| 年・曜日なし | `10/16 12:00〜11/2 11:59` | 年は後述の規則で補完 |
| 終了側の年省略 | `...11月21日...` | 開始年を継承。開始より前になれば翌年 |
| 同日内で日付省略 | `12:00〜23:59` | 開始の日付を継承 |
| 開始のみ(終端なし) | `10/17 4:00〜` | `partial`(startのみ) |
| 終了のみ(期限) | `2026年11月4日（水）3:59まで` | `events`ではなく **`reward_until`**(文脈が受取期限)または`partial`(endのみ。表示しない) |
| 文中埋め込み | `受け取り期限は2026年11月4日（水）11:59までです` | `reward_until`として抽出(記事単位) |
| 「頃」「の間で常時出現」付き | `19:00頃〜` / `...11:59の間で常時出現` | 修飾語を除去して解析 |
| 24:00 | `24:00` | **翌日00:00に正規化**(ISO8601に24:00は無い) |
| 曜日誤記 | `10月27日（月）`(実際は火) | 曜日は検証のみ。不一致でも日付を採用し警告ログ |

- **年の補完**(年なし開始/終了): 候補年=記事公開日の年。結果が `published − 180日` より前なら +1年。終了が開始より前なら終了を+1年。年またぎ(12月公開で1/5開始、12/28〜1/3)をフィクスチャで固定。
- **項目と継承**: eventは `title_named?`(名称が見出しでなく記事タイトル由来)・`inherited?`(見出しに期間が無く記事主期間を継承)を持ちうる。詳細は §4.5。
- **項目アンカー**: eventは `anchor?`(見出し h2/h3 内の `<a id>`)を持ちうる。export の `url`、選択/レビューのURL、詳細パネルの「公式記事」リンクは `記事URL#anchor` で該当項目へ飛ぶ(無ければ記事URL)。自身に `<a id>` の無いh3項目は直前のh2のアンカー(キャンペーン情報の節)を使う。
- **複数期間**: 1記事に複数の `▼…期間` がありうる。名称は直前の見出し(h2/h3/▼見出し前の太字等)から取得、取れなければ記事タイトル+連番。**全体期間と日別枠の統合方針(確定)**: 同一の期間見出し(▼…)内で、最初の範囲を全体期間(event)とし、**開始がその範囲内に収まる後続の範囲は個別eventにせず、そのeventの `slots: [{start,end|null}]` に畳む**(省略可。畳むものが無ければキー無し。20261015_2のガチャ日別枠・`10/17 4:00〜`等)。範囲外の後続(「1回目/2回目/3回目」等)は別eventとする。**補足**: 終了が日付のみ(`〜11月4日(水)`)ならその日の23:59まで(従来は0:00で最終日の枠が範囲外になり別eventに分かれた)。1行に同日の時間帯が複数ある(`8:00〜9:00 12:00〜13:00`)場合は全てslotsに畳む。slotsはexportされ、詳細パネルに日付×時間帯の表で出す(バーは全体期間で1本)。表示ラベル(バー/詳細)は括弧「」『』≪≫〈〉と先頭末尾の「、」「。」を付けず中身は残す。
- 入力はテキスト化済みの行。h2/h3見出しは行頭 `# ` で渡し、直前の `# ` 行を名称にする(無ければ `<記事タイトル> #<連番>`)。実装: `src/period.ts`(`parseArticle`)、ゲーム日は `src/gameday.ts`。
- 終了のみの期限は、行または見出しに「受取/受け取り」を含むときのみ `reward_until`(複数あれば最新)。含まない「使用期限」「利用期限」は eventにせず警告のみ。`▼配信日時` 等、期間/期限を含まない見出し配下の日時は無視。
- `parse_status`: `ok`(start・endあり) / `partial`(startのみのevent、または`reward_until`のみ。受取以外のendのみ期限は無視) / `none`(期間・期限とも抽出不能)。
- **表示**: `ok`は表示。`partial`(startのみ)は開始ゲーム日にのみ「終了未定」付きで表示。**`none`は非表示**(保存はし、collect終了時に件数を標準出力。分類レポートは `npm run report:unparsed`(標準出力のみ・本文不使用。`src/unparsed-report.ts` がタイトル/カテゴリで 獣神化解禁・メンテ/アップデート・タイトルに開始日のある開催告知・お知らせ等に分類し、件数・例・提案を表示))。

### 4.3 週表示UI
旧カレンダーの要点: 1週間分のイベント+キャンペーンをまとめて表示 / 「詳細」で開催期間と報酬受取期間 / 日切替4:00。
- 7日(ゲーム日)のガント。**今日(4:00境界のゲーム日。ページ読込時点で決定)起点のローリング7日のみ**(前週/次週/今日ボタンは無く、「<」「>」の移動のみ)。曜日は日付ヘッダに表示。日付の行の左端に年月(`2026年11月`)を出し、1月1日の目印には年も付ける。移動は表示範囲(§4.8)の中まで(端で「<」「>」が無効)。
- バー/日付クリックで**日別詳細パネル**: 短縮した項目名、開催期間、公式記事へのリンクのみ(カテゴリ・記事タイトルは出さない)。
- **チェックボックス(カテゴリ絞り込み)は無い**。表示項目の選択は §4.5 のファイルで行う。
- 時刻はJST表示。データ最終更新時刻を画面に表示。
- **フォント**: 画面も Discord の画像も、同梱の **Noto Sans JP**(npm `@fontsource-variable/noto-sans-jp`〈OFL。バージョン固定〉。ビルドで `dist/assets` に入り、使う文字の分だけ読み込まれる。外部のフォント配信は使わない)。端末・生成環境によって字形が変わらないようにするため。予備は `system-ui` など(`body` の `font-family`)。
- 見た目: バーはセクション色、今日列の強調、**画面の色はライト/ダークを切替(画面上部のボタン。既定はライト=白背景で、OSのダークモードには合わせない。選んだ色は localStorage に保存。撮影モード〈Discord の画像〉は常にライト。`src/theme.ts`・`:root[data-theme="dark"]`)**。**上部のボタンは文字でなく記号**(インラインSVG。`src/icons.ts`): 切替先を表し、ライト中は月(ダークにする)・ダーク中は太陽(ライトにする)、週表示中は月のカレンダー(月表示にする)・月表示中は週のカレンダー(週表示にする)。意味は `aria-label` と `title`(ツールチップ)で伝える。`<` `●` `>` は従来どおり記号、スマホ幅は横スクロール(行ラベルは固定)。幅600px以下(スマホ縦)は余白と行ラベル(5.5rem)を詰めて週表示の7日が横スクロールなしで収まる(月表示は横スクロール)。ボタンは高さ約40px以上、詳細パネルの表は横にはみ出さない。公式の画像・ロゴは使わない。

**ガント型への置換**: 週ビューは公式アプリ風のガント型。7日分の日付ヘッダ(日・曜日、土青/日赤、今日強調、クリックで日別詳細)、セクション見出しごとに1イベント=1行、期間を日付列にまたがる横バーで表示(週端で切れる側は角を落とす。終了未定は開始日のみ縞模様)。バー/日付クリックで詳細。判定は§3のゲーム日(4:00)。カテゴリ→セクション対応と除外カテゴリは `src/sections.ts` の1ファイルに集約(未掲載カテゴリは「その他」)。上記のカード表示・「継続」印は置換された。
**週/月表示**: ヘッダの1つのトグルボタン(ラベルは切替先の「月表示」/「週表示」)で切替。週=今日起点の7日(初期)、月=**起点の日から同じ日の翌月の前日まで**(初期は今日が左端。例: 10/27起点なら10/27〜11/26の31日。存在しない日は月末日で代用し、代用後の日が次の起点になる=`monthWindow`/`addMonthsToDay`)を列にした同じガント(今日列強調・クリック詳細・ラベル挙動は共通)。両ビューとも「<」「>」で前後へ(週は7日ずつ、月は同じ日の前後の月へ)。「●」ボタン(ツールチップ「今日/今月に戻る」)で基準画面(週・月とも今日が左端)に戻る(基準なら無効)。カレンダー部分は横ドラッグ/スワイプで**ドラッグ中に**表示がずれる(放すのを待たない。週・月とも列幅ごとに1日。ドラッグ直後のクリックは無効。月表示の狭い画面のタッチは従来の横スクロール)。表示中の期間はカレンダー内(日付ヘッダ)に出るためヘッダに別表示しない。データの無い月表示は「この月に表示するイベントはありません」。切替・移動で詳細パネルは閉じる。日表示は日別詳細パネルが担う。**バー長**: バーの左端/右端は、その列内の**暦の時刻**(JST 0:00〜24:00)の割合で詰める(12:00開始=列のちょうど半分から、12:00終了=列の半分まで。4:00=1/6)。バーの列は**暦日(JST)**で決める(列=0:00〜24:00。日別詳細パネルと「今日」はゲーム日のまま)。週/月端で切れる側・終了未定の右端は従来どおり。**同じ表示ラベルのバーは1行にまとめる**(離れた期間も同じ行に並べる。重複しない前提)。行(日付・セクション見出し・イベント行)は列数に応じた同一最小幅で、横スクロールしても罫線・見出しが途切れない。
**母集団ビューは廃止**: UI・`population.json`・タブを削除。収集済み全体の確認は `npm run candidates`(選択ファイル)と `--report` で行う。

### 4.3.1 ラベル短縮(`src/label.ts`)
表示ラベル(ガント行名・詳細見出し・バーのaria-label)だけを短縮する。バーのツールチップは全文、選択/判断のキー(`item`)・正本・`config/judge/decisions.json`は変えない。優先順:
1. **定例キーワード**: 項目名(`event.name`)が `config/display/recurring.json` の `keywords` のいずれかを含めば、ラベルはそのキーワードのみ(上から最初の一致)。現在: 覇者の塔 / 絶級トーナメント / 未開の幻洞 / 禁忌の獄 / 破界の星墓(ユーザ表記「破壊の星墓」は公式表記「破界の星墓」と解釈。要確認)。**追加は `keywords` に1語足すだけ**(コード変更不要)。
2. **定型句の除去**(`trimBoilerplate`): 末尾の ` #N` / 先頭の【…】/ `(追記:…)`・`(追加情報:…)` / 日付・時刻(`10/9 19時より` 等。期間は詳細に出るため) / 語頭以外の `[が|を][期間限定で][再](登場|出現|開催|実施)` が `!`/`！`または文末に続く箇所以降(`が期間限定で登場！クリアで…`) / 末尾の `について`・`!`。結果が空なら元の名前。
3. **省略しない**: 長くても `…` で切らない(長ければ折り返す。全文はバーのツールチップにも出る)。
既知の割り切り: 定例キーワードは部分一致のため、同じキーワードを含む別項目は同じラベルになりうる(全文はバーのツールチップ)。定型句除去は最初の `開催!` 等以降を切り捨てる(後続は説明句が大半のため)。
詳細パネルは `短縮名 / 開催期間 / 公式記事リンク` のみ。期間は `M/D(曜) HH:mm 〜 …` で、**年をまたぐ項目だけ両端に年を付ける**(`2026/12/31(木) 12:00 〜 2027/1/5(火) 11:59`。`periodText`)。手動項目の `hide_start` / `hide_end`(`config/schedule/manual.json`)は期間の開始 / 終了を出さない(片方だけなら `〜 終了` / `開始 〜`、両方なら詳細パネルの開催期間の行ごと出さない。バーのツールチップ・aria-label も同様。仮置きの期間の常設クエスト用)。**報酬受取期限は表示しない**(別記事の内容を取り込み大半が誤りになるため。`reward_until` のデータ抽出は残るが画面には出さない)。

**週⇄月の切替**: 切替では、切替前の画面の左端の日を切替後の左端にする(週→月は `monthStart = weekStart`、月→週は `weekStart = monthStart`)。移動(< >)やドラッグで動かした左端も引き継ぐ。● の基準(今日が左端)は今日のまま。
**行ラベルの上書き**: クエスト・キャンペーンの行ラベルで1行(全角約16文字。ラベル欄14rem−余白÷0.8rem太字。目安は全角15.5文字相当=全角1・半角英数0.6・記号/空白0.35)に収まらないものを、`config/display/label-overrides.json` の規則(項目名から「」『』を除いた文字列に `match` を含む最初の規則の `label`、`desc` があれば2行目)で指定の短い表記にする(`src/label-override.ts` `labelOverride`、`rowLabel` で適用。折り返さない)。ガチャの行ラベルには適用しない。詳細パネルの名前は変えない。例: 「ノーコンテニュー報酬でわくわくの実が2個排出」→「ノーコンティニュー報酬2倍」(月次のタイムボーナスは「タイムボーナス報酬2倍」)。スワイプトレジャー・DREAMDAZE Ⅳ・ガチャ系は指定により変形しない。パワー系は「スコア稼ぎパワー/至宝パワー/学びパワーの出現確率UP」、「特Lの園が出現」、「CM視聴でレアアイテム確率UP」(1行)、「究極でスコア報酬5倍」。「原生の神殿 感謝の間」は非表示(`config/judge/rules.json` の `genshin-kansha`。英雄の神殿の感謝の間は表示)。英雄の神殿の並びは ノーコン→タイムボーナス→消費スタミナ→チャンスバトル→特L(`config/display/order.json` の `rows`)。**表記の一貫性**: 「の出現確率UP」に揃える(バルーンのオラゴンの出現確率UP)、「が」を付けない(クエストで金卵の排出率2倍・フレンドポイントの獲得量5倍)、「絶級で〜」「究極で〜」(「で」でつなぐ)、書庫ポイントは「書庫ポイント消費0」の1種類、経験値は「クリア経験値2倍」、動詞は「出現」(登場にしない。感謝の間が出現)、ノーコンテニュー(公式の表記)、期間限定クエスト系は1行にくっつける(期間限定クエストユーフリィム・13周年記念クエストテンシュリー)。上書きの表記が15.5em以内であることはテストで保証する。手動調整の仕組みの名前・形式は後でまとめて統一する予定(暫定)。
**日付の表記**: 画面に出す `M/D` は `MM/DD` に0埋めする(`10/07(水)`。`dayLabel` / `padMonthDay`。期間・日別の時間帯・詳細パネルの日付表・公式サイト収集時刻)。時刻も `HH:MM` に0埋めする(`08:00`。`padTime` / `padDateTime`)。保存データは変えず表示時に整形する。年付きは `2026/01/01`(年は残す)。名称中の数値(「1/2」)は日付として出す箇所にだけ適用するので変えない。
**セクション開閉**: セクション見出し(`role=button`・`aria-expanded`・Enter/Space可)のクリックでそのセクションのイベント行を畳む/開く。畳むと見出しに行数を付けて `クエスト(5)` と表示。初期は全て開く。状態は `localStorage`(`collapsedSections`、セクションIDの配列。失敗しても動作)に保存し、週/月切替・移動・ドラッグでも維持。ドラッグ直後のクリックは無効(既存の抑止を共用)。

**更新ボタン**: `npm run dev` のときだけヘッダに「更新」ボタンを出す(本番ビルドでは出さない)。押すと開発サーバの `POST /api/collect`(`scripts/collect-api.ts`)が `npm run collect` → `npm run candidates` を順に実行し、完了後に `data/` を再読込して表示を更新する。実行中はボタン無効・「更新中…」、結果は隣に表示(失敗時は出力の末尾)。コマンドは固定(リクエストから引数を取らない)。ローカル接続(loopback)のみ許可し、他サイトからの呼び出し(CSRF/DNS rebinding)対策として Host がローカル・Origin が同一・`Sec-Fetch-Site` が same-origin/none・カスタムヘッダ `X-Requested-With: update-button` を要求(違反は403)。同時実行は409、**直前の実行終了から5分は429**(失敗時も。メモリ上の値なので dev サーバ再起動で解除。礼節: operations §4 の連続実行回避)。各ステップは10分でタイムアウトして中断、出力は直近16KBのみ保持。取得量は `collect` の既定(直近2ページ)。

### 4.3.2 同一ラベルの統合と並び順(`src/week.ts`)
- **統合**(`mergeSameLabel`。ガント生成時と `initialState` で適用、冪等): 同じセクション・同じ表示ラベル(§4.3.1 `shortLabel`)で**期間が重なる**(端が接する・同時刻を含む)イベントを1行に統合。期間は和集合(最も早い開始〜最も遅い終了。どちらかが終了未定なら未定)、報酬受取期限は最新。代表は開始が最も早いイベント(id・名前・URL)。同ラベルでも期間が離れていれば別イベントのままだが、**表示は同じ行に並べる**(#68。例: 絶級トーナメントの前回と次回)。
- **並び順**: クエストセクション内の並びは §4.3.5(小見出し順)。他セクションは開始順。
- 自動非表示ルール(§4.6): 「ミッション」を含む項目(期間限定ミッション・SNS投稿ミッション等)は off(`mission`)。ただし次は先に評価され on/off が上書きされる: 「期間限定〜ミッション」(`title_regex: 期間限定「[^」]*ミッション」`、`limited-mission`。括弧なしの「期間限定ミッション登場」は off)、「CM視聴ミッション」(`cm-mission`)、「活用ミッション」(`activation-mission`)、「登場!ミッションクリアで」(`mission-clear-bonus`。`gacha` より前)は on(ただし「期間限定で登場!ミッションクリアで」は `limited-clear-bonus` で off)。`「覇者の塔シーズンズ」開催` は off(`tower-seasons`)。ただし判断の記憶(`decisions.json`)が優先。
- 追加ルール(`config/judge/rules.json`。`gacha-on` より前): `monst-generation`(ガチャ「モンストジェネレーション…」は値引き券対象でも on)、`monpass-trial`(モンパスお試しキャンペーン。on)、`guardian-debut`(守護獣…初登場。off)、`unlock-announce`(獣神化・真獣神化…解禁。off)。モンスト×メルカリギフトは既存の `collab-keyword` で off のまま。
- off ルール(先勝ち。`config/judge/rules.json` の順): `new-event`(新イベント)、`sns-campaign`(SNS/リポスト/引用ポストキャンペーン)、`striker-record`、`voice-frame`(ボイスセット/フレーム)、`manga`、`guide-heading`(「〜をチェック/を紹介/を確認しよう/を受け取ろう/について」で終わる案内見出し)、`new-character-intro`(新(限定)キャラクター)、`game-campaign-umbrella`(見出し「ゲーム内キャンペーン」)、`orb-back-challenge`。on は `bonus-box-balloon`(使用回数/ラッキーバルーン)。`new-event` は `activation-mission` 等より前なので「新イベント」を含む題名は常に off。ユーザの判断が一貫していたパターンを一般化したもので、誤りは判断の記憶で上書きする。

### 4.3.4 毎月決まった日の項目(`config/schedule/monthly-days.json` / `src/monthly.ts`)

### 4.3.5 セクションの振り分けと並び(`src/sections.ts` `sectionOfEvent` / `src/week.ts`)
- カテゴリが event でも、名称に `config/display/order.json` の `groups.campaign` のうち `match` が `"name"` の小見出しの名前(ノーマルクエスト・強化進化クエスト・英雄の神殿・追憶の書庫・守護獣の森・モンスポット・イベントクエスト)を含む項目は**キャンペーンセクション**に表示する(クエストセクションには出さない)。
- **クエストの小見出し(`questGroup` / `config/display/order.json`)**: クエストセクション内を次の順に小見出し(`.g-group`。キャンペーンと同じ見た目・開閉なし)でまとめる。該当行が無い小見出しは出さず、畳んだセクションでは出さない。
  1. **イベントクエスト**(表示順は定例より前。順は §4.3.8): イベントガチャ(§4.3.7。新イベント・コラボのガチャ)と**同じ項目を同じラベル・期間で写したもの**(イベントid末尾 `~event`。ganttSections で生成。日別詳細の一覧には出ない)。並びは 通常のイベント→コラボ、各々開始順。
  2. **定例クエスト**(毎月決まった日程で出現する項目): 名称が `order.json` の定例クエスト(`role` なし・`match: "words"`)の `words`(覇者の塔→絶級トーナメント→禁忌の獄→破界の星墓→未開の幻洞)を含む。この順に並べる。
  3. **絶級クエスト**: 降臨スケジュール(`轟絶|黎絶|滅絶 …降臨`)。**滅絶→黎絶→轟絶**の順。
  4. **期間限定クエスト**: 名称に「クエスト」を含む(13周年記念クエスト等)。
  5. **超究極クエスト**: 名称に「超究極」を含む。行ラベルは `キャラ名（補足）`(補足=`超究極・兵クエスト` の 兵、傑など。無ければ `キャラ名` のみ=括弧ごと省く。`superUltimateLabel`)。キャラ名が取れない名称(`超究極クエストが…`)は従来表示。
  判定は上の番号順(先に一致した小見出し。例: 覇者の塔を含む超究極は定例)。同じ小見出し内の同順位は開始順。

- 「召喚の鍵」(`summon-key`)・「クエストクリアで「ジンロン」出現」(`jinlong-appear`)・「オラ様とピッチで駆けろ」(`ora-pitch`)は off。強化進化クエストは英雄の神殿と同様に名称でキャンペーンへ振り分ける(クエストセクションには出さない)。
- 「ラックボーナス優待」は off(`luck-bonus`)。「招待感謝バッジ」を含む項目は off(`invite-thanks-badge`)。
- **小見出し配下の行ラベル**: 小見出しが対象を示すので、キャンペーンのグループ行は2行表示の**説明(細かい字)だけ**を主表示(2行まで)にする(例: 英雄の神殿の行は「チャンスバトルが必ず出現」)。説明が無い行は従来どおり。クエストの小見出し配下は、超究極のみ上記のキャラ名表示で他は従来表示。
- **小見出し内の並び(`config/display/order.json` の `rows` / `groupSortCmp`・`questCmp`)**: 「名前順」は表示ラベル(`rowLabel`)の五十音順(`Intl.Collator('ja', {numeric:true})`。かな→漢字の順で、漢字はJIS順相当=訓読みの読み順にはならない。数字は数値順)。
  - クエスト: 定例=keywords順 / 絶級=滅絶→黎絶→轟絶、階級内は名前順 / 期間限定クエスト=名前順 / 超究極=補足なし(キャラ名が取れないものを含む)→補足あり(補足の名前順)、同じ補足内はキャラ名順。

- **降臨スケジュール**: 轟絶/黎絶/滅絶の記事の `▼初出現日時`(`RAID_LABEL`)を期間として取り込み、名称は記事タイトルから `黎絶 キャローネ降臨`(`raidName`)。クエストセクションでは「絶級クエスト」の小見出し。`raid-first-appearance`(タイトルに 轟絶/黎絶/滅絶 と 初登場)は on。降臨は継承元(`events[0]` 相当)にしない。

### 4.3.7 ガチャセクション(`config/display/order.json` の `classify.gacha` / `gachaGroup`)
- セクション「ガチャ」(キャンペーンの次=最下段)。名称に「ガチャ」を含む項目が対象。ただし `not_gacha`(ガチャも/値引き券/詳細/について 等)を含むものと、コラボ記事で `ガチャ「` で始まらない付随項目は対象外(従来のセクションに残る)。

- 除外語は `not_gacha`(セクション振り分け)と `rules.json` の `gacha-exclude`(非表示。「ガチャ」を含む項目のみ対象)に同じ語を持つ。`gacha-on` は `not_gacha` 相当の語を含む項目には適用しない。

### 4.13 キャラクター・ガチャセクション(`src/characters.ts` / `src/newlimited.ts` / `config/display/order.json` の `gacha` / `src/data/export.ts`)
ガチャのセクション(id `gacha`・表示名「キャラクター・ガチャ」。クエスト・キャンペーンの下)に、キャラクターの項目を載せる。**1キャラクター=1行**は進化と、ガチャに畳めない新限定。対象は、新限定キャラの追加と、ガチャキャラの進化(獣神化・獣神化改・真獣神化)の解禁。
- **小見出し**(`order.json` の `groups.gacha`。上から **進化**(`role: evolution`。ここにキャラクターの進化の行が入る。名前・順は自由だが、各役割1つ必須)→イベントガチャ→定例ガチャ→期間限定ガチャ。進化の中は**登場順**(バーの開始順。同じ日なら解禁の時刻順)。ガチャに畳めなかった新限定は期間限定ガチャ(既定の小見出し)の行になる。

  - 新限定: タイトルに「新限定」を含む記事。名前は本文の `新限定キャラクター「A」「B」`(無ければタイトルの `新限定(キャラ)「A」`)。キャラ名の括弧(読み仮名など `（…）`)は中身ごと完全に消す。

- **対象ステージ/クエスト(本文由来)**: 記事本文の `▼…対象ステージ` / `▼…階層…クエスト` / `▼対象クエスト` 直下の項目(`・…`、`N階層：…`、日付表の行 `M/D(曜) 属性クエスト`。古い記事の `12月9日（火）  闇属性クエスト` も `12/9(火) 闇属性クエスト` にそろえて抽出。見出しの後ろの注記 `▼対象クエスト（追記：4/24）` も対象)を抽出し、event の `details: [{label, lines[]}]` として正本に保存する。見出し(h2/h3)が event 名と一致すればその event、一致しない(見出し前・期間の無い見出し)ときはステージ/階層ブロックのみ記事の主期間(events[0])に付く。例: 禁忌の獄=「本開催の「禁忌の獄～深淵〜」対象ステージ」、破界の星墓=「本開催の1階層～5階層までのクエスト」、追憶の書庫=「対象クエスト」(日付・曜日・属性)。同ラベル統合(§4.3.2)では同見出しのブロックを項目の和集合にする。

- **本文を保存しない方針との関係**: 保存するのはステージ名・日付・属性の短い項目のみ(文章・画像・報酬説明等は保存しない)。
- **ノーマルクエスト(経験値)**: 名称に「ノーマルクエスト」と「経験値」を含む event は本文不要。`config/schedule/normal-quest-attributes.json`(曜日→対象属性。土=火水木/日=光闇/月=闇/火=火/水=水/木=木/金=光)と期間から、JST暦日(0:00切替)ごとに `M/D(曜) 火・水・木属性クエスト` を表示時に算出する(`normalQuestBlock`)。
- 既存記事への反映: `npm run rebuild`(キャッシュ済み生HTMLから正本とexportを再生成。再取得なし)。

### 4.10 カレンダーの台帳(`config/judge/calendar/YYYY/MM.md` / `src/ledger.ts` / `npm run ledger`)
収集した項目を、**判定(表示 / 非表示 / 要判断)・理由・記事・期間・内容・項目ID** つきの月別の表として書き出す。自動収集の精度が低いため、人が誤りを見つけ、項目IDで修正の対象を特定するための**読む用の生成物**(編集しない。`npm run update` が毎回作り直し、表示範囲〈§4.8〉の月だけ。範囲外の月は消える)。
- 並び: **表示する項目**は画面と同じ(セクション→小見出し→行。同じ行の複数の期間は開始順)。各セクションの末尾に**非表示・要判断の項目**(開始順。要判断は判断するまで非表示)。メンテナンス、どのセクションにも入らない項目(コラボ記事の付随項目など。セクション列が `-`)はその後ろ。月は暦日(JST 0:00〜24:00)で掛かる月で、複数の月にまたがる項目は各月に載る。
- 列: 判定・セクション・小見出し・表示名・期間(年付きJST `YYYY-MM-DD HH:MM`。`manual.json` の書式と同じ)・内容(詳細パネルのブロックを `見出し: 行 / 行`。先頭3件+`他N件`、全文は公式記事)・出どころ(公式 / 手動(add) / 定例日程)・修正(§4.11)・理由(判断の記憶 / ルール名 / 未判断 / `manual.json の hide`)・項目ID・記事リンク。非表示の理由で、表示の判断(§4.6)の誤りも見つけられる。旧 `config/judge/selection/` の役割はここに統合した。毎月決まった日の項目(`monthly-days.json`)は1行(`monthly:名前`)。イベントガチャの「イベントクエスト」への写しは載せない(元のガチャの行に載る)。
- 公式の記事本文は載せない(§4.7 と同じ。短い名称・日付・URLのみ)。
- この台帳を元にした項目単位の修正は §4.11(`overrides.json`)。「修正」列に修正の有無が出る。

### 4.11 項目ごとの手動の修正(`config/schedule/overrides.json` / `src/overrides.ts` / `npm run override`)
自動収集は精度が限られるため、台帳(§4.10)で見つけた誤りを**項目ID単位**で直す。表示の選択のあと・手動の調整(`manual.json`)の前に適用する(表示の判断のキー `item` は変わらないので、判断には影響しない)。
- **直せるもの(`set`)**: `name`(表示名)・`start`/`end`(JSTの `"YYYY-MM-DD HH:MM"`。期間を直すと日別の時間帯 `slots` は外す)・`group`(クエスト・キャンペーンの小見出し)・`color`・`edge_color`(ラベルの文字の色とバーの縁の色。`src/color-spec.ts`: palette〈`quest-colors.json`〉の色名・`#rrggbb`・`none`=色なし。縁は省略すると文字と同じ。公式・自動(定例ガチャの属性色など)の色より優先。台帳の「修正」列に出る)・`section`(セクションid。`order.json` の `sections` の id。追加したセクションにも入れられる)・`notes`(詳細パネルの見出し直下に出す注記)・`hide_blocks`(詳細で出さないブロックの見出し)・`add_blocks`(詳細に足すブロック `{label, lines}`。同じ見出しは置換)。並びは `order.json`(§4.3.8)で、項目単位の位置指定は持たない。
- **`was`(直す前の公式の値)**: `name`・`start`・`end` を直すとき `npm run override` が自動で記録する。公式の記事が後から変わって `was` と食い違うと `npm run check` が警告する(修正の見直しの合図。自動マージは止めない)。存在しない項目ID・修正が今の公式の値と同じ(不要)も警告。書式の誤りは要確認(終了コード1)。
- 対象は公式の項目のみ(`manual:`・`monthly:` は `manual.json`・`monthly-days.json` を直す)。非表示は `manual.json` の `hide`。
- 台帳の「修正」列に、修正が入った項目と直した項目名が出る。公式の記事本文は書かない(§4.7。短い名称・日付のみ)。
- **セクションの追加**: `order.json` の `sections` に `{id, label, hue, categories}` を足す(`categories` は空でよい)。追加したセクションは小見出しを持たず、`overrides.json` の `section` で項目を入れる。

### 4.5 表示候補と選択ファイル
表示項目はUIではなくファイルで選ぶ。
- `npm run candidates`: 正本から候補を生成し、判断の記憶(§4.6)で表示/非表示を決めて `config/judge/calendar/YYYY/MM.md`(台帳 §4.10。読む用。判定・理由の列を含む。表示用データ `public/data` があるとき)と `public/data/selection.json`(全件の判断から作る)を再生成する。**ユーザが編集するのは `config/judge/needs-review.md` のみ**。
- **候補の単位**=記事内の項目の候補キー(`src/selection.ts` `itemKey`)。項目=記事本文の見出し(h2/h3)単位で、その見出し配下の期間見出し(▼…期間)の期間を持つもの。例: 激・獣神祭の記事から「ガチャ「激・獣神祭」開催!」と「…宝箱「+1」!」「…「オラゴン」の出現確率がアップ!」が別候補になる。
  - キー: 見出し名(NFKC済み)を `normalizeTitle` で正規化。見出し前の期間・最初の期間見出しが告知らしくない(末尾が「!」でない。例「遊び方」。「!」を付けない告知見出しも同様に潰れる制約あり)ときは記事タイトルを正規化したもの(`title_named`)。`normalizeTitle` は日付/時刻(直後の より/から/に/まで 含む)除去、`第1〜3弾`→`第N弾`、`3回目`→`N回目`、`Vol.5`→`Vol.N`、`(追記:…)`/`(追加情報:…)` 注記の除去(除去後に空なら記事タイトルのキー)、`|`→`｜`。同名キーは集約し、件数=その項目を含む記事数、期間=開始が最新のもの。
  - **期間の継承**: 見出しに期間が無い告知項目(見出しが「…!」で終わる。例「SNSキャンペーン開催!」)は、記事の主期間(=記事内で最初に抽出した期間 `events[0]`。大型記事では最初の項目の期間であり、実際の告知期間と異なりうるため印で区別)を継承する。正本eventに `inherited: true` を持ち、選択ファイルの期間欄に `(記事期間を継承)`、日別詳細に同印を表示する。継承しないもの: 「!」で終わらない見出し(購入方法・注意事項等)、見出し配下に期間見出しではない日時(配信日時・解禁日程・ピックアップ日程)があるもの(別日時を記事期間にすると誤るため)。継承項目のidは末尾連番(既存eventのidは変わらない)。
- 選択のキーは上記項目キー。正規化ルールを変えると記憶(`decisions.json`)のキーが現候補に当たらず新規扱い(要判断またはルール)になるため、ルール変更時は `decisions.json` のキー置換を伴うこと。
- 対象: 期間を持ち除外カテゴリでない記事の項目(`none`・除外カテゴリは候補に出さない)。
- **再生成**: 毎回 `calendar/`(台帳)・`needs-review.md` を作り直す(自由記述は残らない)。collect/exportは判断を書き換えない。
- **反映**: 選択ファイルが**ある**とき、週ガントは選択済み候補のイベントのみ表示(未登録の新規記事も未選択扱い=非表示)。**無い**とき(`selection.json`も削除)は従来通り全件。
- 選択状態はCLI(`npm run candidates`)が候補数・新規数・選択済み/未選択数を出力する。UIは `main.ts` が `selection.json` を読み `applySelection` で絞り込む。
- **置き場所と git**: §4.6 の表を参照。`config/judge/calendar/`(台帳 §4.10)は生成物だが、判断の結果を GitHub 上で月ごとに読めるようgit管理する(毎回現在の状態を作り直し、日時を含まない)。旧 `config/judge/selection/` は台帳に統合して廃止した。

### 4.6 判断の記憶・4区分・要判断
収集のたびに手で選ぶ負担を減らす。ユーザが日常的に見る/編集するのは **`config/judge/needs-review.md`(要判断)の1箇所だけ**。
- **ファイル構成と理由**
  | ファイル | 役割 | 編集 | git |
  |---|---|---|---|
  | `config/judge/needs-review.md` | 要判断(同種を1行に集約)。`- [x]`=常に表示 / `- [-]`=常に非表示 / `- [ ]`=保留 | **ユーザ(唯一の編集先)** | 管理外(毎回再生成される一時物) |
  | `config/judge/decisions.json` | 判断の記憶(正本) | 通常編集しない(CLIが取り込む) | **管理する**(判断を履歴に残し、Actions収集・公開でも同じ判断を使うため。中身は正規化タイトル・カテゴリ・判断のみで、タイトルは `data/articles` に既にコミット済みのメタデータ。公式本文は含まない) |
  | `config/judge/calendar/YYYY/MM.md` | 台帳(収集した項目の月別の表。判定・理由・期間・内容・項目IDつき。§4.10。自動生成) | 編集しない(毎回作り直す) | 管理する(読む用。判断・修正を変えたときだけ該当の月の差分が出る) |
  | `config/judge/rules.json` | 自動ルール | 開発者 | 管理する |
  要判断だけを専用ファイルにしたのは、全候補の一覧(60件超)から未判断を探す負担をなくすため。全体確認用の一覧は参照専用の生成物として分離し、編集先を1つに限る。
- **種類キー(`src/decisions.ts` `kindKey`)**: 項目キー(§4.5)の「」『』()の**中身を空**にした文字列(例 `「追憶の書庫」のクエストで金卵の排出率が「2倍」!` → `「」のクエストで金卵の排出率が「」!`)。空にした後の本文(括弧・記号・空白を除く)が **10字未満なら一般化しすぎで誤判定しうるため項目キー自身**を種類キーにする(=その項目にしか効かない)。**カテゴリ込み**(`カテゴリ::種類キー`)で区別。数字・回数の違いは §4.5 の `normalizeTitle` が既に除去する。
- **判断の記憶** `decisions.json`: `kinds`(種類ID→`{decision: on|off, example, confirmed?}`)と `items`(項目キー→on|off、種類より優先)。同種の項目は次回から自動で同じ判断になる。
  - `confirmed: true` は要判断ファイルで人が「この種類」と確定したもの(未確定の記憶と逆の判断で食い違い行を確定した場合は、元の例を反転させないよう列挙された項目だけ `items` に個別記憶)。移行で学習しただけの種類(未確定)は、**例の項目以外にルールが逆の判断を出す場合は誤適用を避けて要判断に回す**(保守的)。
- **分類(優先順)**: 個別の記憶 > 種類の記憶 > ルール(`config/judge/rules.json`。on/off/unsure、first-match-wins。`min_count` は項目キー単位の記事数) > 判断なし=要判断。判断なしは未選択(非表示)。ルールの `title_includes` は項目キーへの部分一致。
- **4区分**: **定例**=判断済みで同種(同じ種類ID)の候補の件数合計が2以上(同一記事内の別項目も数える近似)(表示/非表示は初回判断=記憶またはルールを踏襲。近似であり月数は見ていない) / **自動ON**・**自動OFF**=判断済みで定例でないもの / **要判断**=判断なし。
- **要判断の集約**: 要判断の候補を種類ごとに1行(件数・例示タイトル最大3・直近期間・リンク)に集約。判断1回で同種全体に適用し、`decisions.json` の `kinds` に `confirmed` で記憶。取り込み後その行は消える。保留(`[ ]`)は未選択のまま次回も残る。
- ユーザの基準(**ミッション系は非表示・覇者の塔シーズンズは非表示**。`mission`/`tower-seasons` ルール。既存の判断の記憶のうち該当4種類は off に更新): コラボ不要・ガチャ不要・**販売パック告知は非表示(`pack-sale` ルール。語を含む)**・毎月の恒例イベントは表示・campaignのクエスト内部に関連するものは表示。未知は要判断。
- `npm run candidates`: ①要判断の確定行を取り込み ②4区分に分類 ③`needs-review.md`・`calendar/`(台帳)・`public/data/selection.json` を再生成。
- `npm run candidates -- --report`: 記憶された人の判断を教師にルール単独の判定の一致率・不一致を表示(ファイルは変更しない)。
- `npm run candidates -- --review-issue`: 要判断(未判断)の**集約行のみ**の依頼本文を表示(**ドライラン**。既判断・自動分は載せない。本文は種類・件数・例示タイトル・リンクのみ)。`--review-issue --publish` を付けたときだけ `gh issue create` で発行する(開発では発行していない)。

### 4.8 表示範囲・手動の調整・不要データの削除
- **表示範囲**(`config/display/window.json`): 今日を基準に、過去 `past_months`=12 か月・未来 `future_months`=12 か月。公開サイトのデータ(範囲外の項目・月ファイルは出さない)、カレンダーの移動の限界(`src/window.ts` の `clampToWindow`。`<` `>`・ドラッグ・週月切替のすべて)、判断の月別の表(`config/judge/selection/`)、不要データの削除(`npm run prune`)が同じ値を使う。
- **手動の調整**(`config/schedule/manual.json`、`src/manual.ts`): `add`=公式ニュースに無い項目を足す(`name`・`category`(`event`=クエスト / `campaign`=キャンペーン)・`start`・`end`(JST の `"YYYY-MM-DD HH:MM"`)・`group`(小見出し。省略可)・`color`・`edge_color`(省略可。ラベルの文字とバーの縁の色。書式は §4.11)・`url`(省略可。公式ニュースの記事へのリンク。詳細パネルに出る)・`note`)。行は名前が同じものが1行にまとまるので、公式の項目と同じ行にしたい manual の項目は、名前を公式の表記に合わせる(例: `滅絶 X降臨`)。公式由来の項目と同じ扱い(色や印の区別なし)で、表示の判断(選択)の対象外=常に表示。`hide`=項目ID(`20261030_3#0`)または記事ID(`20261030_3`)を表示から外す(メンテナンスにも効く。データは消さない)。選択の適用(`applySelection`)のあとに適用する。書式の誤りは `npm run check` が検知する。編集は `npm run manual` か Actions の manual(operations.md §14)。
- **不要データの削除**(`npm run prune`、`src/prune.ts`): 表示範囲の過去の限界より前に終わった記事(最も遅い項目の終了=未定は開始、項目が無い記事は公開日)を `data/articles` から削除する。既定は確認だけ、`--apply` で削除。Actions の prune からも実行できる(operations.md §15)。

  "title": "...", "category": "event", "categories": ["event"], "published": "2026-10-22",
  "fetched_at": "2026-10-23T05:00:00+09:00", "lastmod": "2026-10-22T18:00:00+09:00", "content_hash": "sha256:...",
  "parse_status": "ok",
  "events": [
    {"id": "20261022_3#0", "name": "...", "label": "出現期間", "start": "2026-10-27T12:00:00+09:00", "end": "2026-11-21T11:59:00+09:00", "raw": "2026年10月27日(火)12:00〜11月21日(土)11:59"}

  "reward_until": "2026-11-24T03:59:00+09:00"

（新限定キャラの記事は `"gacha_alias": {"from": "Ultra Charismatic LIVE!!", "to": "グリーンファンタジー"}` を持つことがある。§4.3.7。キャラクターを含む記事は、ほかに `"characters": [{"name": "桜", "kind": "獣神化・改", "start": "...", "end": "...", "at": "...", "attr": "闇"}]` を持つ。§4.13）

### 5.2 表示用export
`public/data/events/YYYY-MM.json`（月別。export物は再生成可能なため git管理外(`public/data/` を ignore)。**月境界はゲーム日(4:00)基準**で重なり判定し、月をまたぐeventは両月に含める）+ `public/data/index.json`(月一覧・生成時刻 `generated_at`・最後に公式サイトを収集した時刻 `collected_at`・カテゴリ一覧)。画面上部には `collected_at` を「公式サイト収集: MM/DD(曜) HH:MM (JST)」と出す(無ければ「不明」)。`generated_at` は表示用データを作り直した時刻で、デプロイのたびに進むので画面には出さない。`collected_at` は git管理の `data/collected.json` から引き継ぐ(`collect` が収集を最後まで終えたときだけ更新。中断・`--no-collect`・`rebuild`・デプロイでは変えない)。UIはこれのみ読む(`file://`ではfetchが失敗するため `npm run dev`/`vite preview` 前提)。
- export は **`none` を除く全件**（全カテゴリ）。表示可否は export ではなく選択ファイル(`selection.json`、§4.5)をUIが適用して決める(カテゴリ別 `visibility.json` は不採用)。**公開用export(`npm run build:public`、`src/data/public-export.ts`)のみ**選択ファイルで非表示の項目と12ヶ月超(終了が12ヶ月前より前。終了未定は開始で判定)を除外し、`dist/data/` に出す(`selection.json` は出さない。選択情報が無ければ投げて、未判断の項目を公開しない。メンテナンスは常に残す)。→ 表示方針の見直しでexport再生成が不要になる。
- 各イベント: `{id, article_id, name, title, category, start, end|null, reward_until|null, url, item, inherited?}`(`item`=選択ファイルの候補キー)。
- 保持: 正本は全件。ローカルのexportは全件、公開用exportは表示範囲(過去12か月・未来12か月。§4.8)・表示対象のみ。
- 公開サイトの表示: 画面下部に、自動収集で誤り・抜け・遅れがありうる旨と非公式の注記を常に出す。ビルド時環境変数 `VITE_REPO_URL` があるときだけ Issue 作成ページ(`<URL>/issues/new/choose`)へのリンクを出す(ローカル開発では出ない)。

## 6. 非機能
- Node 24 / TypeScript、フロントはVite+素のTS。テスト: vitest。lint: eslint。テスト/lintはローカル実行(`npm run lint` `npm test`)。PR・mainへのpushでは `ci.yml` が同じ検査を行う。
- パーサは純関数(HTML/テキスト→構造)として副作用と分離し、実記事フィクスチャで単体テスト。
- エラー時は部分成功を保存し、実行ログ(`data/runs.log` JSON Lines、git管理外)に記録。Actions実行時はworkflowログを正とする。
